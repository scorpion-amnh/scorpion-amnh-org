# Content Change Suggestions

This document records proposed content changes identified during site maintenance and migration. **Website copy and bibliographic text are author-owned.** Automated tooling must not edit that content without explicit permission. Items here are suggestions for Lorenzo Prendini (or designated editors) to review, approve, or reject.

## How to use this document

Each entry should include:

- **Location** — file path, page URL, or content ID
- **Original** — text or citation as it appeared before migration (when known)
- **Current** — what the site shows or stores now
- **Issue** — why the change is flagged
- **Suggested action** — what the author might approve (if anything)

When an item is resolved, add **Status** (`approved`, `rejected`, or `fixed`) and the date.

## Policy reminder (added 2026-07-17)

Migration and validation scripts must preserve author wording exactly. When structured data cannot represent an entry faithfully, store the original HTML in `citationHtml` (publications) or flag the entry here rather than rewriting the citation.

## Publications

### AccessScience encyclopedia entry (2006)

- **Location:** `content/publications.json` (2006 section); `/publications`
- **Original** (from pre-migration `app/publications/page.tsx`):

  > **Prendini, L.** "Scorpiones", in AccessScience, McGraw-Hill, https://www.acsciences.com, DOI 10.1036/1097-8542.607800, last modified: April 7, 2006. [PDF](https://research.amnh.org/users/lorenzo/PDF/Prendini.2006.McHill.Scorpions.pdf)

- **Issue:** The Stage 0 migration parser assumed a journal-article shape (`Authors. Year. Title. *Journal* volume: pages.`) and mangled this encyclopedia-style entry. During Stage 1, an automated “fix” incorrectly rewrote the title, journal, and DOI fields without author approval.
- **Current fix (2026-07-17):** Entry now includes a `citationHtml` field with the original wording and PDF link. The publications page renders `citationHtml` verbatim when present.
- **Suggested action:** Author confirms the restored citation matches the intended published form. If approved, no further change needed.
- **Status:** Awaiting review

### Automated publication parsing (all entries)

- **Location:** `content/publications.json` (213 entries); `/publications`
- **Issue:** Entries were generated by a best-effort HTML parser, not manual verification. Non-standard formats (encyclopedia entries, inline DOI text, “et al.” author lists, PDF-only links) may differ subtly from the original JSX bibliography.
- **Current:** Most entries render via structured fields (`authors`, `title`, `journal`, etc.). The renderer inserts `{year}.` after authors, which matches standard articles but **not** every original line (see AccessScience entry above).
- **Suggested action:** Spot-check high-visibility years and any entries that look wrong on `/publications`. Flag additional entries for `citationHtml` where the structured renderer cannot match the original.
- **Status:** Open

### Missing PDF links on journal articles

- **Location:** `/publications`; many entries in original JSX had trailing `<a>PDF</a>` links to `research.amnh.org/users/lorenzo/PDF/...`
- **Issue:** Structured publication schema has no `pdfUrl` field; those links are not rendered for standard entries.
- **Suggested action:** Author decides whether PDF links should be restored site-wide. If yes, approve adding a `pdfUrl` field to the schema and populate from the original bibliography.
- **Status:** Open

## People

### Person image paths cleared during validation

- **Location:** `content/people/*.json`; `/people`
- **Issue:** `scripts/fix-content-image-paths.ts` matched JSON `image.filename` values to files on disk. When no file was found, it set `"image": null`, causing placeholder initials instead of photos. **35 people** currently have `"image": null`.
- **Suggested action:** Author supplies correct filenames for affected people, or confirms placeholders are acceptable until photos are available.
- **Status:** Open

### Pío Colmenares — incorrect image remapped by script

- **Location:** `content/people/pio-colmenares.json`; `/people` (Museum Specialists → Current)
- **Original (live page):** Inline JSX uses `src="/images/Pio.jpg"` (file not present in repo → initials placeholder).
- **Current JSON:** `"image": { "folder": "arachnids", "filename": "Scorpion-60.jpg" }` → resolves to `/images/arachnids/Scorpion-60.jpg` (a scorpion photo; passes `validate-content` because the file exists).
- **On disk:** `public/images/people/Pio-Colmenares.jpg` exists and appears to be the intended portrait.
- **Issue:** Wiring `/people` to `getPeople()` would replace the placeholder with the **wrong** scorpion image unless JSON is corrected first.
- **Suggested action:** Set image to `{ "folder": "people", "filename": "Pio-Colmenares.jpg" }` after author confirms.
- **Status:** Open

### Legacy flat image paths vs JSON `{ folder, filename }`

- **Location:** `app/people/PeopleClient.tsx` (inline `src="/images/…"`); `content/people/*.json`; `getPersonImagePath()`
- **Issue:** Many inline paths omit the `people/` subfolder (e.g. `/images/prendini.jpg`, `/images/Tahir.jpg`). JSON stores `{ folder: "people", filename: "…" }` and resolves to `/images/people/…`. Some inline paths point to files that are missing from the repo; JSON may point to different on-disk files or `null`.
- **Suggested action:** Before wiring `getPeople()`, audit each section’s inline `src` against JSON + `public/images/` and document intentional differences here.
- **Status:** Open

### Lab history group photo paths

- **Location:** `content/lab-history.json`; `/people` (Lab Evolution section)
- **Issue:** Stage 0 stored legacy `/images/{filename}` paths; many files live under `/images/people/` with different names. Paths were remapped to on-disk filenames via a script.
- **Suggested action:** Author verifies each group photo still matches the intended image and caption.
- **Status:** Open
